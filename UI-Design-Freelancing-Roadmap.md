# UI Design & Freelancing Roadmap

> A practical roadmap for learning UI design through Figma, building commercial projects, and becoming ready for freelance work.

This roadmap is not a list of topics to finish before creating anything. Learn one concept, practise it immediately, and use it in a complete project.

## How to Use This Roadmap

For every topic:

1. Understand the principle.
2. Complete the tiny practice.
3. Apply it to an actual screen.
4. Compare the result at desktop and mobile sizes.
5. Explain why you made each important decision.

Do not wait to complete every level before designing. You can begin small freelance projects after completing the **Freelance Minimum** section.

---

# Level 1 — Visual Foundations

## 1. Visual Hierarchy

**Learn:** How size, weight, colour, contrast, position, and whitespace determine what users notice first.

**Good enough when:** Someone can identify the headline, supporting information, and primary action within a few seconds.

**Tiny practice:** Design the same hero section three times. Change only typography, spacing, and contrast. Ask someone what they noticed first in each version.

## 2. Layout and Composition

**Learn:** Alignment, balance, proximity, repetition, negative space, visual rhythm, and content density.

**Good enough when:** Every element appears intentionally positioned and related content feels grouped.

**Tiny practice:** Create one balanced symmetrical layout and one asymmetric layout using identical content. Do not use images or colours.

## 3. Grid Systems

**Learn:** Columns, gutters, margins, containers, baseline grids, and how to break a grid intentionally.

**Good enough when:** Elements align across the page without making the composition feel mechanically boxed.

**Tiny practice:** Rebuild one landing-page section using a 12-column desktop grid, then adapt it to a 4-column mobile grid.

## 4. Typography

**Learn:** Typeface categories, type scales, font pairing, font weight, line height, letter spacing, paragraph width, and display versus body type.

**Good enough when:** Headings have character while paragraphs remain comfortable to read.

**Tiny practice:** Create an article page using only one typeface. Establish styles for display, heading, subheading, body, caption, and metadata.

## 5. Colour

**Learn:** Hue, saturation, value, contrast, neutral palettes, accent colours, and semantic colours.

**Good enough when:** Colour communicates purpose instead of merely decorating the screen.

**Tiny practice:** Design one section entirely in greyscale. Introduce one accent colour only for interactive or important elements.

## 6. Spacing Systems

**Learn:** Consistent spacing relationships rather than choosing every gap randomly.

Example scale:

```text
4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96
```

**Good enough when:** Similar relationships use similar spacing throughout the design.

**Tiny practice:** Take an older design and replace every arbitrary gap with values from one spacing scale.

## 7. Images and Visual Assets

**Learn:** Cropping, focal points, aspect ratios, image consistency, compression, licensing, and when imagery actually supports the content.

**Good enough when:** Images feel art-directed rather than randomly downloaded.

**Tiny practice:** Create a three-card editorial row using three unrelated photographs. Make them feel consistent through cropping and treatment without heavily editing them.

### Level 1 Checkpoint

Create a single landing page without effects or animation. It should work using only strong typography, spacing, alignment, imagery, and one accent colour.

# Level 2 — Figma and Interface Construction

## 8. Frames, Sections, and Layer Organisation

**Learn:** Clear page organisation, predictable layer names, logical groups, and separation between exploration and final screens.

**Tiny practice:** Clean one messy Figma screen so another designer can understand its structure without asking you questions.

## 9. Auto Layout

**Learn:** Direction, gap, padding, alignment, wrapping, fixed size, hug contents, and fill container.

**Good enough when:** Changing text or adding an item does not destroy the layout.

**Tiny practice:** Build a navigation bar, button, article row, and pricing card entirely with Auto Layout.

## 10. Constraints and Responsive Behaviour

**Learn:** How elements remain fixed, centred, stretched, or repositioned when a frame changes size.

**Tiny practice:** Build one hero at 1440px, then resize the frame gradually to 768px. Fix every element that behaves incorrectly.

## 11. Components and Variants

**Learn:** Reusable components, variants, properties, nested components, and instance overrides.

**Tiny practice:** Create one button component with primary/secondary styles and default, hover, focus, disabled, and loading states.

## 12. Styles, Variables, and Tokens

**Learn:** Reusable colour, typography, spacing, radius, and theme values.

**Tiny practice:** Create light and dark themes for one small screen using variables instead of manually replacing colours.

## 13. Prototyping

**Learn:** Navigation, overlays, hover states, component changes, transitions, scrolling, and fixed elements.

**Tiny practice:** Prototype a mobile menu and a three-step booking flow. Every interaction must have a clear purpose.

## 14. Developer Handoff Basics

**Learn:** Inspectable layouts, asset export, font documentation, interaction notes, and organised components.

**Tiny practice:** Pretend you are the developer. Inspect your own design and list every unanswered implementation question. Then update the file to answer them.

### Level 2 Checkpoint

Rebuild one finished concept using Auto Layout, components, variables, consistent naming, desktop and mobile frames, and a short clickable prototype.

---

# Level 3 — UI Components and States

## 15. Navigation

**Learn:** Headers, sidebars, breadcrumbs, tabs, menus, active states, and mobile navigation.

**Tiny practice:** Design navigation for a five-page desktop website and convert it into a usable mobile pattern.

## 16. Buttons and Links

**Learn:** Primary, secondary, tertiary, destructive, icon-only, and text-link hierarchy.

**Tiny practice:** Create a CTA hierarchy for a checkout page without making every action look equally important.

## 17. Forms

**Learn:** Labels, helper text, placeholders, validation, error messages, required fields, selection controls, and submission feedback.

**Tiny practice:** Design an appointment form with default, focused, completed, error, disabled, and successful states.

## 18. Search, Filters, and Sorting

**Learn:** Query input, filter groups, active filters, result counts, clear actions, empty results, and mobile filter behaviour.

**Tiny practice:** Design a used-car inventory with filters for price, brand, year, and fuel type.

## 19. Feedback and System States

**Learn:** Loading, success, error, empty, offline, disabled, confirmation, and destructive-action states.

**Tiny practice:** Design four versions of the same dashboard panel: populated, loading, empty, and failed.

## 20. Tables, Cards, Lists, and Data Density

**Learn:** Choose a presentation according to the information and task—not according to trends.

**Tiny practice:** Present the same product data as cards, a compact list, and a table. Write one sentence explaining when each version is appropriate.

### Level 3 Checkpoint

Create a small component library covering navigation, buttons, fields, selection controls, feedback messages, and essential states.

# Level 4 — UX and Product Thinking

## 21. User and Business Goals

**Learn:** A successful design must help the user complete something while supporting the organisation’s objective.

**Tiny practice:** For a barbershop website, write one user goal and one business goal. Design the first screen to support both.

## 22. Client Briefs and Requirements

**Learn:** Audience, objective, pages, functions, content, brand direction, constraints, budget, and deadline.

**Tiny practice:** Turn “I need a modern website” into ten specific questions you would ask before quoting the work.

## 23. Information Architecture

**Learn:** Sitemaps, navigation structure, categories, labels, content priority, and relationships between pages.

**Tiny practice:** Create a sitemap for a car dealership containing inventory, vehicle details, finance, about, service, and contact.

## 24. User Flows

**Learn:** Entry point, decisions, actions, feedback, errors, and completion.

**Tiny practice:** Map the complete path from discovering a barber to confirming an appointment.

## 25. Wireframing

**Learn:** Solve structure and flow before committing to visual styling.

**Tiny practice:** Create three low-fidelity homepage arrangements in 30 minutes. Select one by comparing it against the project goal.

## 26. Content-First Design

**Learn:** Realistic headlines, paragraph lengths, image requirements, content overflow, missing data, and ownership of copy.

**Tiny practice:** Replace every placeholder in one design with realistic content. Test unusually long titles and missing images.

## 27. Conversion Design

**Learn:** CTA priority, trust signals, objection handling, proof, clear pricing, and low-friction forms.

**Tiny practice:** Improve a service landing page so visitors can understand the offer, trust the business, and book within one screen flow.

## 28. Research and Reference Analysis

**Learn:** Study why a design works instead of copying its appearance.

**Tiny practice:** Choose three competitor sites and record their hierarchy, grid, navigation, CTA, strengths, and weaknesses.

## 29. Usability Testing

**Learn:** Give users tasks, observe without directing them, identify repeated confusion, and revise based on evidence.

**Tiny practice:** Ask three people to book an appointment using your prototype. Record where they hesitate and improve only the repeated problems.

### Level 4 Checkpoint

Complete a project from brief to research, sitemap, user flow, wireframes, final responsive UI, prototype, and short usability test.

---

# Level 5 — Accessibility and Responsive Quality

## 30. Accessible Colour and Typography

**Learn:** Contrast, readable sizes, comfortable line lengths, scalable text, and meaning beyond colour.

**Tiny practice:** Audit the smallest and faintest text in one design. Improve readability without destroying its visual character.

## 31. Keyboard and Focus Behaviour

**Learn:** Focus order, visible focus states, skip navigation, and keyboard-operable controls.

**Tiny practice:** Number the intended keyboard order of every interactive element on a form and design a visible focus state.

## 32. Touch and Mobile Usability

**Learn:** Touch targets, thumb reach, mobile navigation, content priority, and reduced precision compared with a mouse.

**Tiny practice:** Test your mobile prototype using one hand. Enlarge or reposition every difficult control.

## 33. Motion and Reduced Motion

**Learn:** Use animation for continuity, feedback, hierarchy, and state changes. Avoid motion that exists only to impress.

**Tiny practice:** Prototype one transition that explains a state change, then design an alternative with reduced motion.

## 34. Responsive Strategy

**Learn:** Reflow, resizing, wrapping, hiding, reordering, breakpoint choice, and responsive imagery.

**Tiny practice:** Adapt one complex desktop section to tablet and mobile. Write what resized, moved, wrapped, disappeared, or changed interaction.

### Level 5 Checkpoint

Run a responsive and accessibility audit on one completed project. Document at least ten improvements and implement them.

# Level 6 — Commercial Project Types

## 35. Landing Pages

Learn offer clarity, storytelling, proof, CTA placement, and conversion flow.

**Practice project:** Create a premium barbershop landing page focused on appointment bookings.

## 36. E-commerce

Learn product discovery, filters, product variants, stock, cart, checkout, delivery, payment, confirmation, and returns.

**Practice project:** Create a focused shop flow: listing, product details, cart, checkout, and confirmation.

## 37. Publications and Editorial Products

Learn reading hierarchy, archive organisation, categories, article templates, authorship, dates, and long-form typography.

**Practice project:** Continue developing Coddiction with responsive screens and defined content states.

## 38. Dashboards and Software Products

Learn dense information, navigation architecture, tables, filters, charts, permissions, onboarding, and settings.

**Practice project:** Design a small analytics dashboard with real data, loading, empty, and error states.

## 39. Booking and Service Websites

Learn availability, service selection, scheduling, customer details, confirmation, cancellation, and reminders.

**Practice project:** Design a complete appointment flow for a salon, photographer, doctor, or vehicle service centre.

# Level 7 — Freelance Operations

## 40. Scoping

Define exact deliverables, screen count, platforms, responsive versions, revisions, assets, prototype depth, and handoff format.

**Tiny practice:** Write what is included and excluded from a fictional $300 landing-page project.

## 41. Pricing

Use fixed pricing for clear deliverables and hourly pricing for undefined or additional work.

Starting reference:

```text
Hourly rate: $15
Minimum engagement: 3 hours
Minimum focused project: $150
Additional simple page: $40–$60
```

These are starting points, not permanent limits. Increase pricing as your evidence, process, demand, and project complexity grow.

**Tiny practice:** Estimate the hours for research, wireframes, visual exploration, responsive design, revisions, and handoff. Compare the total with your fixed quote.

## 42. Proposals and Contracts

Cover the problem, deliverables, timeline, price, payment schedule, revision limit, cancellation, ownership, and licensing.

**Tiny practice:** Write a one-page proposal for a barbershop landing page.

## 43. Payments and Milestones

Use a deposit before starting. A simple arrangement is 50% upfront and 50% before final handoff.

**Tiny practice:** Divide a two-week project into discovery, direction approval, final design, and handoff milestones.

## 44. Feedback and Revisions

Request consolidated, objective feedback tied to the agreed goals. Separate revisions from new requirements.

**Tiny practice:** Rewrite “I don’t like it” into five useful questions that reveal the actual problem.

## 45. Asset and Licence Management

Track the source and licence of fonts, photographs, icons, illustrations, video, and other third-party material.

**Tiny practice:** Create an asset register with columns for asset, source, licence, owner, usage, and delivery status.

## 46. Final Handoff

Deliver organised screens, components, states, responsive behaviour, interaction notes, permitted assets, font information, and a clear completion summary.

**Tiny practice:** Hand one Figma project to a developer friend and ask them to list everything they would still need to build it.

# Freelance Minimum — Complete Before Your First Client

- [ ] I can turn a vague request into a clear project brief.
- [ ] I can create a sitemap or content structure.
- [ ] I can wireframe before polishing the interface.
- [ ] I understand hierarchy, typography, grids, colour, and spacing.
- [ ] I use Auto Layout, components, and clear layer names.
- [ ] I can design desktop and mobile versions.
- [ ] I include essential interaction and system states.
- [ ] I can explain my important design decisions.
- [ ] I can organise a Figma file for handoff.
- [ ] I define deliverables, exclusions, price, timeline, and revisions in writing.
- [ ] I check the licences of every external asset.
- [ ] I collect a deposit before beginning paid work.

You do not need mastery. You need enough control to deliver the agreed scope responsibly.

# Weekly Learning Loop

Use this repeatable cycle instead of endlessly consuming tutorials:

```text
Day 1 — Learn one concept and analyse references
Day 2 — Complete tiny practices
Day 3 — Create wireframes
Day 4 — Design the main desktop screen
Day 5 — Adapt it to mobile
Day 6 — Add states, prototype, and test
Day 7 — Review, document decisions, and publish progress
```

## Final Principle

Do not measure progress by how many tutorials you complete. Measure it by whether your designs become clearer, more usable, easier to implement, and better connected to real user and business goals.
